## Полученные результаты

Собраны все **24 страницы**, **582 строки**, 1990–2011 годы с отсутствующей меткой 2004.
Из них построены **516 пар** с одинаковым названием команды и разницей лет ровно 1;
**66 строк** исключены. **23** будущих результата равны медиане и отнесены к классу 0.
Медиана каждого будущего года вычислена по полной исходной таблице до отбора пар.

| Выборка | Год целевого сезона | Строк |
|---|---|---:|
| train | 1991–2003; меток 2004 и 2005 в парах нет | 338 |
| validation | 2006–2008 | 89 |
| test | 2009–2011 | 89 |

После сравнения на validation выбрана логистическая регрессия с признаками
`win_rate`, `goals_for`, `goals_against`. Pipeline: медианное заполнение пропусков →
StandardScaler → LogisticRegression (`C=1`, `solver=lbfgs`, `max_iter=2000`,
`tol=0.0001`, `random_state=42`). Обучение только на train, порог 0.5.
Один эксперимент с сезонной нормировкой голов снизил validation AUC с 0.7746 до 0.7660;
сохранён исходный вариант. Выбор зафиксирован до оценки test.

| Решение | Validation ROC-AUC | Test ROC-AUC | Test F1 | Test accuracy |
|---|---:|---:|---:|---:|
| Константа по частоте класса в train | 0.5000 | 0.5000 | 0.0000 | 0.5281 |
| Текущий win_rate | 0.7568 | 0.7404 | 0.6522 | 0.6404 |
| Выбранная логистическая регрессия | 0.7746 | 0.7553 | 0.6990 | 0.6517 |

Преимущество по AUC над win_rate небольшое. Оно не доказывает универсального
превосходства: test содержит только три сезона, команды повторяются, статистика
историческая и округлённая. На test 31 ошибка: 25 ложноположительных и 6
ложноотрицательных. Модель и порог после оценки не менялись.

## Воспроизведение

Проверено на Windows, **Python 3.12.14**. Используйте Python 3.12 и запускайте команды
из папки проекта. Для чтения сохранённых результатов достаточно открыть ноутбук;
повторный сбор данных не требуется. Интернет нужен при установке зависимостей.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe run_notebook.py
```

На macOS/Linux вместо `.venv\Scripts\python.exe` используйте `.venv/bin/python`.
Скрипт запуска создаёт временную спецификацию ядра с текущим интерпретатором,
проверяет выполнение всех ячеек и сохраняет outputs в ноутбук. Отдельная установка
глобального Jupyter-ядра не нужна. Ошибка любой ячейки прерывает запуск.

Для интерактивной работы можно открыть ноутбук в Jupyter, VS Code либо загрузить
папку в среду с Python 3.12 и установленными зависимостями. Сначала выберите
соответствующее окружение. В первой ячейке проверяется корень проекта.

Повторный сбор с сайта выполняется **явно**:

```powershell
.venv\Scripts\python.exe -m src.hockey
```

Это заменяет CSV и метаданные новой выгрузкой. Повторный анализ по умолчанию читает
сохранённый CSV и проверяет его контрольную сумму. Если сайт изменится, новая
выгрузка может дать другие результаты; для проверки сдаваемой работы используйте
включённый снимок. В коде нет абсолютных путей к компьютеру автора.

## Проверки и защита от утечки

Проверены типы, обязательные значения, уникальность `(team, year)`, диапазон
`win_rate`, неотрицательность счётчиков и равенство разности голов. `ot_losses`
имеет 224 пропуска в 1990–1998 годах; они сохранены, столбец не используется
в модели. Нельзя восстанавливать число игр как сумму имеющихся исходов старых сезонов.

В test не выполняется выбор модели, признаков или порога. Будущие `win_rate`,
медиана и target не передаются Pipeline. Исследование связи с target использует
train. Обучаемые imputer и scaler используют только train. Для экспериментальных
признаков контекст лиги берётся из текущего сезона t, полностью известного после
его окончания. Нет соединения через отсутствующий календарный год и нет
автоматического сопоставления переименованных команд.

Все ячейки выполнены без ошибок; автоматические тесты пройдены. Повторное
выполнение фиксированного исследования — проверка воспроизводимости, а не новый
поиск решения по test.
